# Event contract v1.0

Pass difficulty is a separate versioned read-only contract; see [formula, API and limitations](PASS_DIFFICULTY.md). It preserves the event and existing metrics contracts.

The authoritative schema is `backend/app/models.py`; FastAPI serves machine-readable OpenAPI at `/openapi.json`. Every event has a stable `event_id`, a `match_id`, a delivery `sequence`, a logical `match_second`, `period`, `source_type`, `schema_version`, and a UTC generation timestamp. Coordinates are normalized to 0–100 from the attacking team's point of view. Team/player references must belong to the fixture.

`POST /api/matches/ingest` now requires `Authorization: Bearer <PULSE_IMPORT_TOKEN>` (503 when unconfigured, 403 when invalid). It accepts a synthetic match and up to 1,000 versioned events. It validates identities, deduplicates identical event IDs, rejects conflicting IDs, sorts out-of-order events by match clock and ID, then assigns contiguous delivery sequence numbers. Imported matches are stored atomically in SQLite (schema migration `user_version=2`, WAL mode) at `backend/data/pulse_xi.sqlite`, or `PULSE_DB_PATH`. They survive process restarts. The built-in fixtures regenerate exactly from their seeds.

`GET /api/matches/{id}/state?at_second=N` and `/metrics?at_second=N` derive values only from events up to N. Goals are counted from `goal` events. Pass completion is completed pass events divided by all pass events. Final-third entry counts completed passes or carries crossing x=66.7. Pressure counts explicit `pressure` events; it is not tracking-derived intensity. Shot quality is an uncalibrated toy position score: `round(clamp((x-60)/100 - abs(y-50)/180, 0.02, 0.8), 2)`. It is **not** xG. No player speed or shot speed is measured.

The WebSocket sends a snapshot then ordered event messages with sequence IDs, allowing clients to deduplicate or resume with `?cursor=N`. It streams a fast deterministic replay for local demonstration; the browser controls the visible replay clock.

`/tactics?at_second=N` returns observed passes, passing links, possession IDs, player contributions, shot and pressure locations, and a 300-second attacking activity series. Pass distance and forward progression are Euclidean and horizontal distances in normalized coordinate units, never metres. Possession sequences group on-ball events by supplied possession ID and exclude defensive pressure events; they are not time-possession percentages. The activity index is `2 × completed final-third entries + 3 × shots + recoveries` for each window `(start, end]`. It is a descriptive count proxy, not xG, win probability or a calibrated momentum model. All output uses events at or before N.

`/insights` now emits goal and rising attacking-activity evidence packets. The tactical rule compares consecutive 300-second windows and reports a rise of at least six index points. The auditor recomputes both numerical claims, checks team attribution, confirms every contributing event ID, rejects future references and verifies the comparison window. `/overlays` emits collision-free 12-match-second cue windows linked to verified packets, with explicit start/end clocks and visual templates; `/overlays/{cue_id}` returns one versioned cue for export. `/recap` retains limited localized, persona-specific **goal** templates with the same evidence IDs and an explicit `verified_rule_based_templates` provider field. It accepts `at_second`, `favorite_team_id` and `favorite_player_id`; focused recaps show only relevant goal moments and a player contribution summary. None of these endpoints implies Foundry model inference.


## Read-only analysis export (analysis-export/1)

`GET /api/matches/{match_id}/analysis-export?at_second=N&category=events|pass|metrics&format=json|csv` uses existing stored/generated events and calculations. Optional `team_id` and `event_type` filter the events category; `event_id` selects a visible pass. No new persistence or simulation runtime is introduced. Negative/out-of-duration cutoffs, unsupported enum values and foreign teams return 422; unknown match or invisible/non-pass selection returns 404; failed deterministic pass verification returns 409. More than 5,000 source events or 8MB serialized output returns 413 without truncation.

JSON schema is exposed in OpenAPI: schema_version, match_id, replay_cutoff, generated_at, category, synthetic, provenance and data. Provenance records actual fixture seed, source event IDs and normalized coordinate units. Build revision uses backend PULSE_BUILD_REVISION if configured, otherwise null; generator version and engine manifest are unavailable, not invented hashes. Event data is serialized by the existing typed model with `type` alias, ordered by delivery sequence. Pass packets are scored and independently reverified with existing pass services. Metrics are the existing cutoff snapshot, with team IDs and units.

CSV has provenance columns followed by deterministic source fields. Nested cells are JSON; null is blank and zero is numeric zero. Leading formula/control prefixes in strings are escaped with an apostrophe. UTF-8 BOM and csv.writer quoting preserve Unicode, quotes and newlines. Empty CSV contains only headers; JSON retains provenance for empty data. Filenames are sanitized and extension fixed; responses use no-store and nosniff. These exports are descriptive replay data, not an experiment manifest or inference output.

Browser-local `bookmark-export/1` contains only source-validated references at/before cutoff and user notes marked unverified. Notes are not sent to the backend. Workspace version 1 and bookmark version 1 are browser-local records, not public API contracts or engine snapshots. Source identity/sequence/time is rechecked after loading; missing references never trigger fabricated playback.


## Match Data Hub / portable packages versions 1 and 2

Database schema 2 is forward-only for older application branches: take a trusted SQLite backup before upgrading an existing schema-1 installation. Do not point an older application at the migrated file. Migration DDL, lifecycle identities and the version marker commit atomically; interruption rolls back and a later startup retries without replacing source events. Concurrent administrative confirmations use the same generation/revision comparison under the SQLite writer lock; exactly one conflicting transition can commit.

- `GET /api/data-hub`: public read-only library, origin, metadata, event counts/categories/coverage, missing optional-field counts, sequence consistency, supplied provenance and configured import availability. No secret is returned.
- `POST /api/data-hub/preview`: requires the server import capability. Validates `MatchPackage` and checks stored conflicts using read-only SQLite access. Does not create a database or persist preview state. Returns match, quality, new/identical/deleted status, deletion_id when applicable, and warnings; conflicts are 409.
- `POST /api/data-hub/import`: same schema and authorization, with atomic full-dataset persistence. Returns match_id/inserted/total. Identical concurrent imports are safe no-ops. Stored complete datasets are immutable; conflicting metadata, event content or membership are 409. Capacity is 100 imported matches. Ordinary import does not delete or overwrite data; separate local-admin lifecycle routes are described below.
- `GET /api/matches/{match_id}/package`: public complete JSON download, all events independent of replay cutoff. Unknown match is 404; incompatible historical data is 422; more than 1,000 events or 2,000,000 bytes is 413 without truncation. no-store/nosniff and a fixed safe filename.

Package envelope: `schema_version: "pulse-xi-match-package/1"`, `match` (existing Match schema, constrained as below), `events` (existing MatchEvent JSON aliases, notably `type`), optional `provenance` with source/exported_at/application_revision string-or-null fields (500 characters each). Unknown fields are rejected rather than silently dropped. OpenAPI exposes nested strict package models. Empty datasets are valid; empty time coverage is null, not zero. Optional coordinates/identifiers may be null, but are never fabricated. Required generation timestamps must include a timezone. Metadata names/title are nonempty up to 200 characters; each team has 1..40 players; IDs are bounded safe identifiers; colors are #RRGGBB. Declared duration is 1..5400 seconds. Events require unique IDs and sequences, valid references and period/clock consistency, no events after fulltime, and monotonic time when ordered by sequence. Sequence gaps and tied timestamps are preserved. Body limit remains 2 MB; 1,000 events max. The JSON boundary also rejects duplicate object keys, non-finite numbers and nesting beyond 32 levels before framework error serialization.

Package ingestion preserves source sequences and does not call the legacy normalization path. It uses existing SQLite transactions and matches/events tables, plus an additive package_metadata table for unverified supplied provenance. Identical reimports retain first-write provenance. Legacy imports retain their existing normalization behavior, but require the same capability and respect cumulative event/byte/library limits; they cannot rewrite package-managed matches. No engine state/RNG or experiment provenance is invented. Package exports retain source/application revision when supplied, otherwise unavailable; exported_at is the current UTC export time. These metadata are not signatures or independent evidence of authorship.

Public read APIs and analysis exports retain their existing contracts. The import token authorizes server-wide writes only, with no authenticated private read model. Configure a high-entropy PULSE_IMPORT_TOKEN before startup, use HTTPS remotely, and never expose it through frontend build configuration. Default remains disabled; Host/CORS/local Origin cannot authorize a write. Browser tests use a dedicated disposable SQLite database and a test-only server token, never a production credential.

## Local dataset lifecycle (SQLite schema 2)

`POST /api/data-hub/matches/{match_id}/lifecycle` requires `PULSE_IMPORT_TOKEN`, explicit `PULSE_ENABLE_LOCAL_DATA_ADMIN=1`, a direct loopback peer and localhost/loopback URL. Proxy/forwarded headers are rejected. This is a trusted local capability model, not production multi-user ownership isolation. Leave local admin disabled on public/proxied deployments.

Body: `{action: "archive"|"restore"|"delete", confirm_match_id, generation, revision}`. No extra fields; generation is a 32-character lowercase hexadecimal dataset incarnation and revision is a positive integer. Confirmation must equal the URL identity. The match must be imported (unknown/generated targets are 404); mismatched confirmation is 422; stale generation/revision is 409; disabled/nonlocal/proxied administration is 403, missing server token configuration 503, invalid token 403. All row checks and changes use BEGIN IMMEDIATE. No bulk operation is offered.

Archive/restore change only archived status and increment revision on a real transition. `GET /api/matches` lists active imports; archived reads by ID, replay, evidence and package export remain supported. `GET /api/data-hub` includes both statuses, dataset generation/revision and safe local-admin availability. Archived datasets count toward the same 100-import ceiling. Listing aggregates counts/coverage in SQL within one read snapshot, avoiding event-model loading. Generation/revision are concurrency controls, not authorization secrets or engine ticks.

Delete atomically removes package_metadata, events, match_lifecycle and matches, adding `deleted_matches(match_id PRIMARY KEY, deletion_id, deleted_at)`. New reads return 404; existing snapshot reads may complete. The ledger prevents delayed ordinary or legacy imports from silently recreating removed data. It is capped at 10,000 identities; entries are not silently evicted. Explicit recovery removes the matching ledger entry and creates a fresh active generation. Stale destructive confirmations cannot affect that generation.

`POST /api/data-hub/recover` requires the same local administration checks. Body is the unchanged canonical MatchPackage; supply its current deletion_id in the X-Pulse-Deletion-ID header, obtained from authorized package preview. Keeping this concurrency identifier outside the body preserves the full existing 2 MB package budget without wrapper overhead. It is not an authorization secret; the import token is still required. Payload schema/checksum and the stored deletion ID are validated; a stale/missing record, conflicting live dataset or full library returns 409 without partial writes. Recovery preserves source events/provenance, not previous archive/revision state. Normal identical imports retain archive state. No arbitrary SQLite file is accepted over HTTP.

The migration from schema 1 preserves all existing matches/events/provenance, creates missing package_metadata, adds `match_lifecycle(match_id PRIMARY KEY REFERENCES matches, generation, revision CHECK>0, archived CHECK IN(0,1))` and the deletion ledger. Existing records receive unique generations/revision 1/active status. Cold startup and migration recheck user_version while holding the writer lock; future versions are rejected. Mutation writes create lifecycle identities in the same transaction. Imported metadata, events and package provenance are read from a consistent snapshot during package export.

## Portable package integrity / version 2

Version 1 input remains supported. New exports use `schema_version: "pulse-xi-match-package/2"` and required `integrity: {algorithm: "sha256", content_sha256: <64 lowercase hexadecimal characters>}`. The digest is SHA-256 of the UTF-8 JSON serialization of normalized typed schema_version/match/events/provenance, excluding integrity, with events sorted by sequence, sorted object keys, ensure_ascii=False, allow_nan=False and separators `(',', ':')`. `MatchPackage.model_dump(mode="json", by_alias=True, exclude={"integrity"})` defines normalized field types/defaults. Whitespace and original JSON object ordering are immaterial. Version 2 without a checksum or with altered content is 422. Version 1 may omit integrity; if supplied it is still verified. Hashes do not authenticate supplied author/source claims. Editing a package to create a different dataset requires deliberate re-authoring and a new checksum, not bypassing failed recovery validation.

Offline `scripts/database-admin.py` is a trusted OS-level operation. SQLite backup API copies a consistent source read snapshot, validates supported schemas (1/2), integrity/foreign keys and payload-vs-column identities, rejects unknown tables/views/triggers, and exclusively creates a new destination. Restore requires the original backup's physical SHA-256. Existing files, including a live database, are never overwritten. To activate a recovered file, stop the app, set PULSE_DB_PATH and restart. Tokens and browser-local notes are not stored in this backup.

Whole-database restore rotates dataset generation IDs and deletion nonces in the new file so forms/recovery requests from before restore are stale. Source match IDs, event IDs/order, provenance, revisions, archive flags and deletion times remain intact. The restored physical-file SHA-256 is reported after these administrative changes. Backup validation currently supports only schemas 1/2 and the documented tables; future engine storage migrations must update this allowlist deliberately.

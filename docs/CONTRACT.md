# Event contract v1.0

The authoritative schema is `backend/app/models.py`; FastAPI serves machine-readable OpenAPI at `/openapi.json`. Every event has a stable `event_id`, a `match_id`, a delivery `sequence`, a logical `match_second`, `period`, `source_type`, `schema_version`, and a UTC generation timestamp. Coordinates are normalized to 0–100 from the attacking team's point of view. Team/player references must belong to the fixture.

`POST /api/matches/ingest` accepts a synthetic match and up to 1,000 versioned events. It validates identities, deduplicates identical event IDs, rejects conflicting IDs, sorts out-of-order events by match clock and ID, then assigns contiguous delivery sequence numbers. Imported matches are stored atomically in SQLite (schema migration `user_version=1`, WAL mode) at `backend/data/pulse_xi.sqlite`, or `PULSE_DB_PATH`. They survive process restarts. The built-in fixtures regenerate exactly from their seeds.

`GET /api/matches/{id}/state?at_second=N` and `/metrics?at_second=N` derive values only from events up to N. Goals are counted from `goal` events. Pass completion is completed pass events divided by all pass events. Final-third entry counts completed passes or carries crossing x=66.7. Pressure counts explicit `pressure` events; it is not tracking-derived intensity. Shot quality is an uncalibrated toy position score: `round(clamp((x-60)/100 - abs(y-50)/180, 0.02, 0.8), 2)`. It is **not** xG. No player speed or shot speed is measured.

The WebSocket sends a snapshot then ordered event messages with sequence IDs, allowing clients to deduplicate or resume with `?cursor=N`. It streams a fast deterministic replay for local demonstration; the browser controls the visible replay clock.

`/tactics?at_second=N` returns observed passes, passing links, possession IDs, player contributions, shot and pressure locations, and a 300-second attacking activity series. Pass distance and forward progression are Euclidean and horizontal distances in normalized coordinate units, never metres. Possession sequences group on-ball events by supplied possession ID and exclude defensive pressure events; they are not time-possession percentages. The activity index is `2 × completed final-third entries + 3 × shots + recoveries` for each window `(start, end]`. It is a descriptive count proxy, not xG, win probability or a calibrated momentum model. All output uses events at or before N.

`/insights` now emits goal and rising attacking-activity evidence packets. The tactical rule compares consecutive 300-second windows and reports a rise of at least six index points. The auditor recomputes both numerical claims, checks team attribution, confirms every contributing event ID, rejects future references and verifies the comparison window. `/overlays` emits collision-free 12-match-second cue windows linked to verified packets, with explicit start/end clocks and visual templates. `/recap` retains limited localized, persona-specific **goal** templates with the same evidence IDs and an explicit `verified_rule_based_templates` provider field. It accepts `at_second`, `favorite_team_id` and `favorite_player_id`; focused recaps show only relevant goal moments and a player contribution summary. None of these endpoints implies Foundry model inference.
